# Security audit report (production findings, consolidated)

Date: 2026-11-14. Written for: the project owner. Sources: the read-only production audit of 2026-11-14 (five agents, evidence in the scratchpad `audit/` and `audit2/` folders), the independent review of the browser and voice work, and local tests. **No production change was made by any of this work**, no secret appears in this report, and nothing was committed, pushed or deployed.

Labels: **Implemented** (code exists), **Tested locally**, **Pending approval** (a prepared procedure exists, the owner has not approved it), **Blocked** (cannot proceed), **Production verified** (checked on the live servers). "Verified" below means a read-only check on the live system or the live bundle's own text.

## 2. What was changed locally (and what it proves)

- `apps/web/src/lib/security/rate-limit.ts`: new `canonicalClientKey()` and a hardened `clientIp()` (same signature). `tests/unit/client-ip.test.ts`: 36 tests (header priority, last-entry rule, repeated header, padding, bad text including lists, ports, brackets, zone ids, hex and short forms, 2,000 characters, IPv4-mapped IPv6, /64 collapsing, compressed and expanded spellings, warning throttle without the address, and the limiter itself). Website suite: **444 passed in 31 files; `tsc --noEmit` clean**. Existing tests encoded none of the old behaviour (every test and Playwright spec that sets the header uses one value), so **no existing test was changed**; the Playwright specs were not run (they need a running site).
- What this does **not** prove: that the app is unreachable around nginx (S-02), that the proxy header is what the app really receives (the audit could only see what nginx logged), or anything about real shoppers' address distribution.

## 3. Route-level changes the orchestrator must make (outside `src/lib/security`)

1. `src/app/api/assistant/chat/route.ts` line 51 calls `clientIp(req)` twice and maps a non-IP to `0.0.0.0`. Compute it once, and decide the bucket policy for `unknown`: the Agent will see `ip:0.0.0.0` (its own limits 40 per minute, 10 new conversations per hour, 2 concurrent, shared by every such request). Recommended: keep the mapping but also count such requests as a metric, and consider refusing (503) in production when no proxy header is present at all, since nginx always sets one.
2. `src/app/api/assistant/voice/{transcribe,speak}/route.ts` use `guestOrCustomerIp(clientIp(req))` (same mapping; `voice-agent.ts`). Apply the same policy.
3. No change is needed in the Agent for the website's normalised address.

## 4. Prepared procedures (none executed)

`tools/ops/prepared/`: 01 nginx log redaction, 02 block direct access to 8090, 03 bind 8090 to loopback and recreate web then the tunnel, 04 monitoring. Every script refuses to run without `I_HAVE_APPROVAL=yes`, was checked with `bash -n`, and was shown to refuse without the approval variable. The sed expressions of 01 and 03 were tested on copies of the observed lines (matching tab and space variants, ignoring a custom format, another file and a commented line; the 03 expression changes only the one port line). **Not tested:** any script against a real server, the nginx `log_format` with `map` capture (nginx is not available here; `nginx -t` inside the script is the check and it restores automatically on failure), the iptables rules, persistence of the firewall rule across reboot (untested; possibly absent), and the monitoring scripts on a real journal (their parsing pipeline was tested on sample lines only). The tunnel's `docker run` options come from the audit's `docker inspect`; the QA step must re-verify them (the recreate script also refuses if they differ).
